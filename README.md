Github is a powerful and useful tool that many game developers and programmers use. Blah blah blah, I heard they use Github and use branches.

main = Core, working version of the game
yourBranch = any immediate changes you make are staged to this branch. this is where you can more freely and without consequence make changes and save states of your code for your own purposes, etc.
test = when you are done with yourBranch, you can then push it to test where you can make sure the changes you have made did not break the game in any way and the state of the game is stable and working.

i heard processes go somewhat like this:
yourbranch -> test -> main

in short its just so you can record stages of your own development and steps, and be able to reference, backtrack etc without too much consequence. this is especially important when working in teams. lots of people will make their own edits at different points in time etc etc, and especially when the time comes for all those changes to come together in code is where merging happens. then after you merge changes together you have to make sure the game is working fine
